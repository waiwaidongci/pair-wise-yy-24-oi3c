# 电台播出与版权窗口排程

一个不依赖第三方包、使用 SQLite 和标准库 HTTP 服务的电台排程项目。系统把“计划排期”和“实际播出”分开保存，支持地区授权、日期窗口、禁播时段、节目冷却、赞助商间隔、直播临时替换、实播对账与版权越界检查。

## 运行

需要 Python 3.11+。

```bash
python app.py
```

默认端口为 `8111`，页面地址是 <http://127.0.0.1:8111>。第一次启动会创建 `radio.db` 并写入三条演示排期。也可以设置端口和数据库位置：

```bash
PORT=9000 RADIO_DB=/tmp/radio.db python app.py
```

## 测试

```bash
python -m unittest discover -s tests -v
```

测试覆盖完整流程：排期、临时替换、播放日志、按日期对账；同时覆盖时间重叠、未授权地区和实播错节目等失败场景，以及复制到下周的键位映射、四类冲突收集、冲突不写入与整套保存。

## 主要 API

- `GET /api/state`：节目、排期和最近对账异常
- `POST /api/programs`：创建节目并授权地区
- `POST /api/programs/{id}/regions`：追加地区授权
- `POST /api/schedule`：创建排期
- `POST /api/schedule/copy-week/preview`：按来源周日期+地区预览复制到下周（不写入），返回键位映射与全部冲突
- `POST /api/schedule/copy-week`：确认后整套一次保存；存在冲突时返回 409 且不写入任何排期
- `POST /api/slots/{id}/replace`：替换计划节目并重新校验
- `POST /api/playout`：登记实播记录
- `POST /api/reconcile`：按日期生成漏播、错播、时长偏差和超授权异常

准备排期时填写 `air_date`、`start_time`、`program_id`、`region`。页面会直接显示校验错误，不会保存失败的排期。

## 复制到下周

运营可在页面“复制到下周”区域选择来源周内任意一天（按周一至周日定位该周）和地区，系统只取当周**未取消**的排期，按相同星期键位与开播时间映射到下周对应日期，然后对目标周逐条检查：

- 与目标周已有排期或复制条目之间的**时间重叠**
- 目标星期的**禁播时段**
- 节目授权窗口到期、节目停用、**地区未授权**
- 同一赞助商节目的**间隔政策**（间隔不足或撞档）

只要有一处不合适，预览就按节目和时间列出全部问题且不写入；无冲突时给出可确认的预览，确认后整套排期在一个事务内保存。复制产生的排期状态为普通 `planned`，之后仍可照常替换、登记实播与对账。
